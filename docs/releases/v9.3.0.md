# Review Mesh v9.3.0

This release addresses RM-16: reviews whose managed artifact disappears during
publication or after a successful run. The historical deletion actor remains
unknown; these fixes protect the lifecycle and make surviving evidence usable.

## Artifact lifecycle

- Active runs write `.jsonl.active` staging files outside completed-file cleanup.
- Before final verification, core copies the complete artifact from its owned
  descriptor to a private recovery file, using bounded reads and verifying its
  full checksum against the bytes core serialized.
- Managed publication never overwrites an existing file. Failure retains recovery
  evidence and emits `run.persistence_failed` with exit 3, storage stage, safe
  native error code and recovery reference when available. It never emits a clear
  `run.completed` for failed publication.
- Successful persisted runs register the managed artifact, private recovery copy
  and optional caller details copy in the index. If the primary later goes
  missing, readers verify a registered identical copy and report
  `artifact_resolution.source: alternate`.
- With `persist_runs=false`, successful details/index publication is followed by
  descriptor-based wiping of temporary core bytes. Failed publication retains
  recovery evidence. Empty private marker files can remain.

## Recovery and diagnostics

```text
review-mesh recover RUN_ID --artifact PATH_TO_DETAILS_OR_RECOVERY_FILE
review-mesh status RUN_ID --json
review-mesh report RUN_ID --format json
```

Recovery verifies run identity, all artifact records, terminal checksum, byte
count, result count and safe filesystem identity before updating an orphaned
index. A mismatched, modified, active, symlinked or conflicting artifact fails
closed. Recovery leaves the supplied file untouched and caller-owned. It does
not invoke models or assert that the current worktree matches historical evidence.

A complete artifact from failed index publication can also be explicitly
imported. That case is marked `recovered_from_unindexed`; original stdout
delivery remains recorded as failed. Recovery does not rewrite the original
process exit or pretend its terminal event was delivered.

Status/report/findings/retry preserve typed artifact errors, safe native error
codes and recovery guidance. Index updates retain an immutable previous-index
journal and coordinate through an owned lock; an interrupted dead-owner update
can be recovered without replacing an unrelated file.

Initial publication uses an exclusive hard link to a fully synced, verified
staging inode. Filesystems without hard-link support fail explicitly; no unsafe
overwrite fallback is used. Private index publication aliases and archived
previous-index journals remain available for recovery.

## Retention and compatibility

Legacy retention now requires a completed artifact with a matching private
writer ownership manifest. It skips current-format files, active runs, indexed
or orphan-indexed runs, caller copies, modified files and unmarked historical
files. It never removes a caller-owned details copy. Unmarked history and v9
managed/recovery artifacts are preserved rather than guessed to be evictable;
automatic `max_runs` trimming applies only to proven legacy-owned publications.

New indexes use schema v2; v1 indexes remain readable and recoverable. Existing
v9 request/config/result and artifact-record schemas are unchanged. Public event
v6 adds the terminal `run.persistence_failed` event. Use v9.3.0 or later to read
the new index and storage-failure contracts.

Release validation covers removal/replacement before final verification,
post-success primary deletion, exact-copy recovery, interrupted index updates,
retention coexistence, and Windows/Linux binaries reviewing a real 57-file diff
followed by missing-primary fallback and v1 orphan recovery without model calls.
