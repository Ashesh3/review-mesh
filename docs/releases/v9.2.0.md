# Review Mesh v9.2.0

This release addresses the September 5 v9 pilot: valid first-run configuration,
readable changed files, reliable observed coverage, admission-based timeouts,
bounded result repair, and practical run recovery.

## Operations

```text
review-mesh status RUN_ID --json
review-mesh status RUN_ID --json --details
review-mesh cancel RUN_ID
review-mesh pause RUN_ID
review-mesh resume RUN_ID
review-mesh diagnostics list RUN_ID
review-mesh diagnostics export RUN_ID ARTIFACT_REF NEW_FILE
review-mesh diagnostics cleanup RUN_ID [ARTIFACT_REF]
```

Pause performs a graceful stop, retaining completed results. It does not serialize
an in-flight provider conversation; resume retries unfinished work. Within an
active review, page and coverage repairs retain the existing conversation.

`--details-file` publishes at finalization; status links to the active artifact.
Invalid raw pages can contain source or credentials and remain private. Successful
pages are wiped after persistence. Failed pages become eligible for cleanup after
24 hours, triggered by later spool creation, or can be wiped earlier with the
cleanup command. This is not a continuously running expiration service. Empty
owned directories and control markers can remain after safe cleanup.

## Compatibility and verification

Public v9 request/config/result/event contracts remain supported. Private record
writers advance resolution to v3 and attempt, terminal and coverage to v2; this
release reads earlier declared versions. Use v9.2.0 or newer to inspect newly
written artifacts.

The release acceptance fixture runs a real 57-file changed Git review through
the Windows and Linux binaries using both pilot model identities, exact reads,
Unicode diff delivery and a repaired four-byte header overflow. The provider is
a local deterministic protocol fixture; it does not establish live model
quality or live service availability.

Live Windows structured doctor with the pilot gateway: `gpt-6-astra` passed all
readiness facets. `claude-opus-5` passed authentication, streaming, changed-file
access, observed coverage and diff delivery, but its result-page response was
blocked with `finish_reason=content_filter`. That run remains inconclusive with
an explicit provider-filter diagnostic; it is not treated as a successful review.

Release assets: Windows x64 executable, Linux x64 glibc executable, and
`SHA256SUMS.txt`, built with Bun 1.4.0.
