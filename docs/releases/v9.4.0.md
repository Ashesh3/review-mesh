# Review Mesh v9.4.0

This release addresses the Collector run investigation across source delivery,
failure handling, evidence continuity, structured repair, reporting and policy.
The original run remains correctly inconclusive; these fixes do not turn its
unaccepted output into a clean review.

## Reliable execution and evidence

- Provider timeouts normalize to `provider_timeout` before public validation.
  Output serialization/transport errors retain their first event, sequence,
  stage and native error. They do not cancel unrelated reviewers or invent
  expired deadlines. Durably collected results survive stdout failure.
- Delivery failure is recorded in the artifact before sealing, or in the run
  index for a late heartbeat/terminal-write fault. A successful terminal write
  no longer hides earlier delivery failures.
- Core supplies missing immutable source ranges in deterministic bounded batches
  with readable UTF-8 and exact byte validation. Coverage is credited only after
  the provider receives a successful request containing the source.
- Inspection telemetry exposes the effective turn limit, remaining turns,
  inspected files, deficits and remaining bytes. Finalization has a separate
  bounded phase, including after the last allowed source read.
- Recoverable attempts retain source, analysis, session identity and result
  assignment. New conversations replay any inherited source credit. Local
  inspection/acquisition exhaustion is explicitly non-circuit-qualifying;
  provider circuit diagnostics retain the failure that opened the circuit.

## Structured repair and useful failure reports

- Result continuation requests carry accepted header/page obligations. Validated
  candidates and unresolved finding declarations survive page repair, complete
  regeneration and outer retries. An empty retry cannot erase a candidate.
- Representation byte counts and coverage digests are computed from received
  content by the host. Missing declared items/fragments and invalid evidence
  remain failures. Repair targets affected pages/items and preserves valid
  siblings; unresolved drafts are durable private diagnostics marked unverified.
- HTTP diagnostics retain bounded sanitized provider code/text, model, phase,
  turn, request size and correlation IDs. Oversized, hanging and HTML error
  bodies are bounded; request echoes and credential-shaped content are redacted.
- Markdown renders summaries, notes, findings, evidence, severity/confidence,
  coverage deficits, attempts, timing, delivery errors and retry guidance even
  when `review_markdown` is empty. Retained coverage-incomplete results and
  unverified drafts are distinguished from accepted reviews.
- Default JSON reports omit raw record expansion; `report RUN_ID --format json
--raw` includes it. Current v9 findings output carries outcome/coverage/exit
  metadata, so an empty findings array is unambiguous. Retrieval command exit
  zero still means successful retrieval, not review clearance.

## Smaller artifacts and explicit policy

- Snapshot manifests are persisted once per digest, with compact per-reviewer
  coverage references. Supporting files are labeled `supporting`, not falsely
  claimed to be Git-untracked. Their identity remains part of retry freshness.
- Historical coverage v1/v2 stays readable. New coverage v3 and snapshot
  manifest v1 records verify digest, counts, order and references. Missing or
  inconsistent references fail closed.
- Evidence preflight reports snapshot bytes/ranges/unavailable files and flags
  large full-file cost relative to diff-based deadline estimates. These are
  feasibility diagnostics, not model-completion guarantees.
- A lens emits `lens.quorum_unreachable` as soon as remaining candidates cannot
  achieve a clean quorum. Useful evidence collection continues with an honest
  inconclusive result; policy is never silently lowered.

Optional trusted configuration profiles are deliberate policy changes:

```toml
[execution]
review_profile = "strict-evaluation"
```

`strict-evaluation` requires all configured models and provider groups per lens.
`routine-review` requires up to two passing models and two groups. Both preserve
configured evidence, applicability, adjudication and primary distribution.
Omitting the setting retains every existing quorum value. For a single-model or
small roster, routine mode does not imply outage tolerance. Check `describe`
and its topology warnings for the effective policy. Set
`distribute_primaries = true` and lens `change_coverage.relevant_paths` explicitly
when desired; model prose cannot waive mandatory coverage.

## Compatibility and upstream investigation

Request v3/config v7/result v4/public events v6 remain current with additive
fields/events. New private record kinds include run errors, source preflight,
unverified drafts and shared manifests. Index v2 adds optional late delivery
diagnostics. Use 9.4.0 or later to read these new fields/records; existing artifacts
are still supported. The local read-only dashboard marks retained incomplete
results as unaccepted.

The separate local copilot-api investigation reproduces a nonstreaming pre-header
retry delay that can exceed the documented
edge idle window. It does not establish the deployed revision or original
400/524 causes. Copilot-specific strict-schema fallback is an intentional
compatibility adaptation, so Review Mesh continues to validate model output.

Release validation includes focused regressions, full tests, typechecking,
portable and Windows/Linux standalone builds, exact historical artifact replay,
and a deterministic strict five-model review of 35 files with over 1.6 MB of
source. The exact original live Collector worktree is absent; a real rerun
requires its full checkout/base commit, credentials and provider availability.

Final validation: 1,187 tests passed with 9 expected skips. The separately
enabled standalone suite passed all three tests, covering Windows/Linux artifact
contracts, the 57-file pilot fixture and the strict five-model large-source
fixture. Typechecking, touched-file formatting and artifact hashes passed.
