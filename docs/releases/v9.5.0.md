# Review Mesh v9.5.0

This release addresses the remaining v9.4 rerun failures: oversized accumulated
contexts, opaque tool exceptions, adjudication bookkeeping, selected-reviewer
diagnostics, and the absence of independent review-quality evaluation.

## Bounded source review and context admission

OpenAI-compatible models now have a request budget derived from `/models`
capacity metadata or explicit trusted adapter settings. Without metadata, the
fallback is a 128,000-token context. Every request reserves output and safety
headroom and budgets the entire JSON envelope, including tools and schemas.
The current tokenizer-independent estimator uses UTF-8 bytes as a conservative
token upper estimate; diagnostics label it `utf8_upper_bound`, not an exact
provider token count. Metadata source and effective limits are recorded.

Optional trusted adapter settings:

```toml
[adapters.gateway]
type = "openai_compatible"
base_url_env = "REVIEW_MESH_OPENAI_BASE_URL"
api_key_env = "REVIEW_MESH_OPENAI_API_KEY"
context_window_tokens = 128000
max_input_tokens = 110000
max_output_tokens = 8192
```

Large changes-only reviews run bounded evidence segments followed by cross-file
synthesis. Each segment records exact delivered ranges/digests plus structured
model reasoning: candidate findings, unresolved questions and concrete scenario
checks. Completed source is not repeatedly appended to later requests. A final
empty pass cannot discard retained findings, including candidates from a
malformed checkpoint or one interrupted by context-limit recovery.

Context-too-large responses retain safe numeric limits and correlation IDs.
The adapter reduces the effective budget and retries smaller segments without
crediting rejected delivery. Completed segment checkpoints survive recoverable
attempts; changing the cancellation signal does not erase them. Model metadata
and estimates cannot guarantee provider completion, and impossible instructions,
unresolved synthesis or oversized retained obligations still fail honestly.
Full-scope reviews retain the existing tool flow and whole-request admission by
default. Trusted adapters can set `semantic_checkpoints = true` to require
segmented scenario collection for full-scope reviews and small quality fixtures.
This option is required when producing reports for the quality scorer.

Segment scenario checks are **model reasoning**, not executed tests or proof
that every branch is correct. Source coverage remains distinct from semantic
conclusions and runtime validation. Prompts require concrete empty/boundary/replay
reasoning and discourage unsupported blanket passes.

## Exact reads and actionable errors

- Readable UTF-8 preserves BOM bytes. BOM files no longer fall back to base64
  unnecessarily or create three-byte continuation fragments.
- Harmless relative forms such as `./src` and `src/` normalize consistently.
  Invalid or escaping paths return recoverable tool errors; traversal remains
  blocked.
- Unexpected exceptions retain a safe class/message category, last operation,
  phase, model, turn and stack fingerprint in private diagnostics. Raw stacks,
  source, queries and arbitrary exception properties are excluded. These local
  failures are non-circuit-qualifying.
- Context errors are classified before echo redaction and rendered with safe
  vocabulary and numeric limits. Request echoes and credentials remain protected.
- Selected-reviewer status includes latest failure, attempt count and timing;
  `--details` includes only that reviewer's attempts, preflight, segment and draft
  metadata. It no longer silently ignores details for a selected reviewer.

## Adjudication and quality evaluation

Adjudication header count, candidate digest and page total are host-owned.
Assignments supply total obligations plus exact per-page decision IDs. Wrong
representation metadata can be normalized while preserving the original raw
digest chain. Missing, duplicate, foreign or reordered decisions still fail.
Validated decisions survive targeted repairs and outer retries; durable drafts
record assigned, accepted and missing IDs, with bounded private decision records.

The new [quality evaluation guide](../quality-evaluation.md) provides synthetic
buggy/corrected fixtures for replay persistence, bounded retrieval and eligibility
boundaries. The answer key and executable oracle live outside the reviewer
workspace. The evaluator checks actual behavior and source locations rather
than finding-title keywords, and reports false positives separately. Fixture
and evaluator tests do not claim a model detected the bugs; score actual raw
review reports to measure model quality.

## Compatibility and validation

Existing requests/configuration/results and old run artifacts remain readable.
New optional adapter context settings, budget/exception diagnostics, segment
progress and private `reviewer.segment`/`reviewer.exception` records are additive.
Use v9.5.0 or newer to consume those new records. Strict quorum, source identity,
candidate preservation and adjudication are not weakened.

Validation covers malformed checkpoint recovery, context-budget reduction,
transient resume, UTF-8/BOM boundaries, exact EOF receipts, independent quality
oracles and adjudication assignments up to 256 candidates. Standalone acceptance
uses five different context capacities with a 35-file source workload larger
than any one request. Live model-quality or original private PR clearance is
not inferred from mocked infrastructure acceptance.

Final verification: 1,256 tests passed with 9 expected skips; all three separately
enabled standalone acceptance suites passed. Source/test typechecking,
touched-file formatting, historical artifact reads and release checksums passed.
