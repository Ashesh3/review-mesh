# Review Mesh v9.6.0

This release repairs local completion failures in bounded semantic review. It
does not relax full-source coverage, candidate preservation, adjudication or
quorum requirements.

## Recoverable reads and metadata-first review

- PR/work-item context and the authoritative changed-file inventory are delivered
  before diff and snapshot analysis. A bounded input manifest distinguishes absent,
  queued, partially delivered and delivered inputs; large supplied metadata is
  not misrepresented as missing.
- Follow-up reads support typed `snapshot`, `diff` and `context` requests, legacy
  pseudo-paths and harmless relative path prefixes. Requests stay confined to the
  captured snapshot. Invalid paths or ranges retain the checkpoint and mandatory
  queue and return a safe error plus a host-owned unresolved question. Reviewers
  must explicitly resolve that error ID after correction or deciding the read is
  unnecessary; a later empty checkpoint cannot silently erase it.
- Overlapping follow-ups are deduplicated against pending bytes. Already delivered
  rereads cannot jump ahead of mandatory source work. Arbitrary UTF-8 byte ranges
  use exact base64 when they cannot be decoded without changing bytes.
- Private segment diagnostics retain follow-up requests, outcomes and resolved
  question IDs. Exact delivery receipts remain separate from model reasoning.

## Targeted checkpoint recovery

- Supported assistant text-part arrays and fenced JSON are normalized. JSON mode
  is explicitly requested in the prompt for gateways that require that keyword.
- Every rejected checkpoint records bounded failure stage, response bytes/hash,
  finish reason and safe schema issue paths. Missing content, malformed JSON,
  invalid schema and output truncation are no longer mislabeled as inspection
  budget exhaustion. Provider content filtering is not retried as format repair.
- Validated candidate objects are host-owned. Repair may omit or re-emit them
  without requiring identical prose; re-emission cannot overwrite the original.
  Invalid declared candidates and unresolved questions must still be repaired.
  Mutation diagnostics retain field names and hashes, not raw response text.
- Final nonpaged results also accept supported assistant text-part arrays.
- Segmented prompts no longer require an unavailable `coverage_status` tool.
  They use host-managed input manifests and receipts instead, including during
  final paging. Impossible reviewer header page counts are rejected before
  acceptance, allowing targeted header repair rather than a full assembly restart.

## Consistent diagnostics and progress

Known nonnegative integer token statistics and the fixed `utf8_upper_bound`
estimator survive persistence, report, selected/whole status and dashboard
projections. Credentials, arbitrary token fields and invalid statistic values
remain redacted.

Evidence, synthesis and finalization have explicit operation phases. Heartbeats
and reviewer views retain the current segment, last completed checkpoint,
delivered/remaining required bytes, unresolved-question count and input budget.
Historical records remain readable and are not rewritten to invent missing state.

## Validation and limits

New deterministic acceptance uses a multi-segment diff, 35 substantial source
files and supplied metadata. It exercises mixed valid/rejected reads, explicit
correction, a preserved cross-file candidate/question, full byte coverage,
synthesis, final output and adjudication through the real CLI and HTTP adapter.
Targeted tests cover malformed/filtered/truncated responses, immutable candidate
retention, Unicode boundaries, queue conservation and diagnostic projection.

Simulated-provider acceptance is infrastructure validation, not proof of model
bug detection. Original private-workload completion and provider reliability must
be measured with a fresh live rerun. HTTP gateway timeouts and invalid empty-choice
provider envelopes remain explicit failures; circuit accounting is unchanged.

The new diagnostic fields are additive; use v9.6.0 or newer to consume its new
artifacts. Existing request/configuration formats and legacy artifacts remain
supported.
