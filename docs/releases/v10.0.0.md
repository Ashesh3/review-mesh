# Review Mesh v10.0.0

Review Mesh now runs reviews through vendor-owned coding-agent SDKs. The custom raw-inference engine, context budgets, segmented review loops, and provider retry framework have been removed from native review execution.

## Model routing

| Model family                           | Review harness     |
| -------------------------------------- | ------------------ |
| OpenAI                                 | Codex SDK          |
| Anthropic                              | Claude Agent SDK   |
| Other supported models, including Kimi | GitHub Copilot SDK |

Model identifiers are preserved. Model access depends on the selected account or compatible gateway; routing does not grant access. The SDKs own model calls, repository tools, conversation history, compaction, and transient provider retries. Review Mesh coordinates the trusted roster, concurrency, deadlines, cancellation, configured gate policy, and complete result delivery.

## Breaking changes and migration

- The `openai_compatible` backend is retired. Existing configuration remains readable, but reviews require explicit migration to `sdk` or the appropriate native SDK adapter.
- Native coverage uses `native_attested`: the agent reports inspected paths and scope completion. This is distinct from the historical exact-byte snapshot proof. Informational caveats do not invalidate explicitly completed scope.
- Native retries rerun the configured review instead of inheriting historical snapshot evidence. Terminal SDK failures are not automatically retried by Review Mesh.
- Command-only configurations retain their existing contracts. Mixed command/native reviewer rosters must be separated.
- Claude/Codex credentials and custom provider URLs require explicit trusted references. A gateway must support the protocol used by each SDK: Responses for Codex, Anthropic Messages for Claude, and Chat Completions for Copilot BYOK.

Generate and inspect a migration preview before applying it:

```powershell
review-mesh config migrate-sdk --json > sdk-config-apply.json
Get-Content -Raw sdk-config-apply.json | review-mesh config apply --json
review-mesh describe . --json
review-mesh doctor . --structured-output
```

The preview preserves reviewer/model settings and credential-variable names without expanding secret values. It contains trusted instructions, like `config export`, so keep the preview private. Applying it retains revision checks and atomic writes. Downloading this release does not change installed configuration.

See the [migration guide](https://github.com/Ashesh3/review-mesh/blob/v10.0.0/docs/sdk-migration.md) for separate vendor credentials, gateway prefixes, and Copilot login behavior.

## Bundled runtimes

Windows and Linux x64 executables bundle all three native runtimes and extract them on first use. A separate Codex, Claude, or Copilot CLI installation is not required. Each artifact is approximately 600 MB; Git, configuration, and credentials remain external.

The runtimes execute as managed noninteractive child processes. Claude/Copilot use hidden Windows launchers. The pinned Codex SDK does not expose a `windowsHide` option, so a universal no-window guarantee is not established. Claude/Copilot use native read/search tools; Codex uses its native read-only sandbox and command tools. An independently enforced outer filesystem boundary is not claimed.

## Results and reliability

- Preserves the v6 JSONL/v4 reviewer-result interfaces, reports, read-only dashboard, and historical artifact readers.
- Preserves validated reports and findings when later SDK cleanup or output delivery fails, while marking the affected run incomplete.
- Bounds SDK startup and review concurrency, preserves cancellation, and records SDK and runtime versions separately.
- Validates native structured results and citation ranges without creating model-facing page, checkpoint, or repair conversations.
- Detects observed workspace content changes through streamed content hashes; ACL/timestamp changes alone do not cause false mutation reports.
- Handles Codex strict nullable output schemas and Claude strict-schema annotations and gateway `/v1` prefixes at the SDK boundary.

## Validation and limits

Source verification includes formatting, application/test TypeScript, the full test suite, and the portable build. Windows/Linux release binaries are checked against the full-result/artifact contract and each bundled runtime's startup, handshake, and shutdown.

Live synthetic reviews through the configured gateway produced structured reports with all three SDKs. Codex passed the seeded-defect and corrected controls. Kimi raised a false positive on the corrected control; Claude also returned a non-gating finding on that control. These checks establish integration, not general review accuracy. Large-context native compaction was not benchmarked.

See [validation evidence](https://github.com/Ashesh3/review-mesh/blob/v10.0.0/docs/sdk-validation.md). SDK ownership removes custom inference machinery; it does not guarantee exhaustive defect detection or eliminate account quotas and provider failures.
