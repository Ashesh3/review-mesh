# Review Mesh v9.7.0

This release addresses local recovery gaps exposed by the v9.6 live comparison.
It does not treat source delivery, smaller requests, recovered checkpoints or
provider canaries as proof of a complete or correct review.

## Output-aware checkpoint recovery

- Explicit trusted `max_output_tokens` values above 8,192 are honored within
  advertised model capacity, the 65,536 safety ceiling and context headroom.
  Without an explicit setting, requests start at 8,192 or the lower advertised
  limit. A larger advertised limit permits bounded adaptive growth; unknown
  capacity does not grant an invented larger allowance.
- A checkpoint ending with `finish_reason:length` can increase its permitted
  output allowance and rebalance input headroom. When growth is unavailable,
  evidence ranges/count are reduced. Minimal unsplittable evidence fails
  explicitly instead of repeating an identical request indefinitely.
- Recovery is finite: at most six output adjustments per checkpoint. Synthesis
  can try a compact response without dropping retained findings or open questions.
  User-selected reasoning effort is not silently reduced.
- Validated candidates and invalid declared candidate obligations survive recovery.
  Rejected source ranges receive no delivery credit. Previously reduced input
  limits and unavoidable schema/state overhead constrain output growth.
- Numeric schema repair hints now preserve exclusive bounds, such as a line
  number greater than zero. Intermediate repair outcomes can be `pending`.

## Safe provider telemetry

Private `reviewer.response` records retain each completed chat envelope's
allowlisted numeric usage, finish reason, correlation IDs, effective output cap
and cap source. Both envelopes of an empty-choice retry remain inspectable.
Raw reasoning text, opaque reasoning state, credentials and arbitrary usage keys
are excluded. Missing counters mean unavailable, not zero usage.

Reports expose compact response summaries and detailed records. Token statistics
survive the existing credential-safe sanitizer. `response_body_truncated` and
`model_output_truncated` distinguish transport completeness from provider output
limits; legacy `truncated` remains readable. Provider usage is reported telemetry,
not independently measured tokenization.

## Bounded evidence retention

Later segments retain exact small PR/work-item metadata, a bounded acknowledged
range map, and recent scenario reasoning linked to checkpoint IDs and source/diff
context. Large metadata remains explicitly available through context reads;
omitted paths/facts are counted rather than presented as absent.
Completed-segment summaries in each request are also bounded, with an omitted
count and digest; full checkpoints remain in the artifact. This prevents many
small segments from consuming the entire context with growing summary history.

Scenario facts remain **model reasoning, not executed validation**. Their links
identify matching file paths or diff context, not verified source-line spans.
Candidates and unresolved questions are maintained separately and are not evicted
with the bounded fact view.

Follow-ups may include `question_id` and `purpose`. Already-delivered requests are
labeled, not silently suppressed; their explanations survive delayed delivery
behind required evidence. Prompts ask the model to state what a reread established
and resolve the corresponding question where justified.

## Cooldown-aware provider admission

An otherwise eligible reviewer can wait for an open provider circuit's cooldown
within its existing deadlines, without holding execution or provider-concurrency
slots. One reviewer reserves the half-open probe; other waiters wake on a state
change or deadline. Cancellation remains responsive.

Progress and heartbeats expose the cooldown queue reason, next retry time and
causal failure. Waiting itself is not fabricated as a failed provider attempt.
Actual retry limits, qualifying-failure rules and strict pass/provider quorum are
unchanged. Persistent gateway or model failures still produce honest incomplete
results; this is not a breaker bypass or an unbounded retry policy.

## Compatibility and validation

Existing request/configuration formats and old artifacts remain supported. New
response diagnostics, pending repair state and cooldown progress are additive;
use v9.7.0 or newer to read artifacts containing those new fields.

New regressions exercise successive output truncations with retained findings,
numeric usage privacy, delayed reread purpose, evidence-memory limits, single
half-open admission, deadlines and cancellation. End-to-end acceptance uses the
real CLI and a synthetic HTTP responder to require complete source delivery,
synthesis, nonempty findings and adjudication after output recovery.

Real-provider availability and original-workload completion require separate live
verification. No private comparison source or credential data is included in this
release, and deterministic acceptance is not a model accuracy score.
