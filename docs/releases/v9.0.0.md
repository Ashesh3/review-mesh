# Review Mesh v9.0.0

V9 bounds unattended review time and requires each clean reviewer to satisfy its
changed-file inspection policy. It preserves complete accepted results in one
immutable artifact and makes incomplete coverage explicit.

## Current contracts

| Contract                    | Writer version                            |
| --------------------------- | ----------------------------------------- |
| Request                     | 3 (request 2 remains accepted)            |
| Configuration               | 7 (versions 1–6 migrate on explicit save) |
| Reviewer result             | 4                                         |
| Adjudication result         | 2                                         |
| Public event                | 6                                         |
| Immutable artifact          | 2                                         |
| Report / status / dashboard | 2 / 3 / 2                                 |

`concise-jsonl` is the default. Use `--output-mode full-jsonl` for every complete
sanitized reviewer result on stdout. Every mode requires an artifact; when
`diagnostics.persist_runs = false`, provide an exclusive `--details-file PATH`.

```text
review-mesh describe . --json
review-mesh review . --details-file review-details.jsonl
review-mesh review . --output-mode full-jsonl
review-mesh status RUN_ID --json
review-mesh report RUN_ID --format markdown
review-mesh findings RUN_ID --deduplicate --json
```

The terminal event reports `run_outcome`, `gate_outcome`, and `coverage_outcome`
separately. `run_outcome` is `clear`, `gate_findings`, `inconclusive`, or
`cancelled`; `gate_outcome` is `no_gate_findings` or `gate_findings`. Partial
coverage always produces an inconclusive result, even when findings are known.
Exit codes remain 0 clear, 1 complete with gate findings, 2 pre-run error,
3 partial coverage or runtime/persistence failure, and 4 cancellation.

## Time and progress

Adaptive deadlines use the captured file count and UTF-8 diff size:

| Maximum files / diff                    | Deadline   |
| --------------------------------------- | ---------- |
| 3 / 16 KiB                              | 15 minutes |
| 10 / 64 KiB                             | 30 minutes |
| 50 / 512 KiB                            | 60 minutes |
| Larger, truncated scope, or full review | 90 minutes |

```toml
[execution]
deadline_mode = "adaptive"
no_progress_timeout_ms = 300000
heartbeat_interval_ms = 30000
```

Fixed deadlines use `deadline_mode = "fixed"` with `run_deadline_ms` between
60,000 and 14,400,000. Queue, probe, retry, continuation, adjudication, and
fallback consume shared absolute budgets. Observable attempts reset the
no-progress clock only for new response bytes, tool identities, or result pages.

## Changed-file proof

```toml
[agents.correctness]
kind = "generic"
required_input = []
lens_deadline_ms = 1800000

[agents.correctness.change_coverage]
relevant_paths = ["src/**", "tests/**"]
minimum_inspection = "full_file"
proof = "observed"
```

This snippet extends an otherwise complete agent configuration. A full-file
observed review needs every required snapshot byte plus the complete tracked
diff. Deleted paths use the deleted diff; untracked paths require the snapshot.
Partial reads, inaccessible files, truncated scope, and relevant binary/oversize
files remain coverage deficits. Several partial reviewers cannot combine into
a clean quorum.

OpenAI-compatible, Claude, and Copilot use Review Mesh-owned read tools. Codex
and external command adapters use explicitly labelled attested proof. Attested
claims require the exact core-pinned digest and never become observed evidence.
Mixed-adapter lenses derive attested proof when any candidate cannot mediate
reads. Explicit observed proof on an incapable adapter fails preflight.

## Results and findings

Semantic pages are bounded to 32 KiB and echo core-assigned identity, sequence,
and previous-page digest. Results retain the 16 MiB serialized ceiling and
lossless large narratives. Claude's SDK exposes parsed structured output; its
page serialization is labelled `sdk_canonical_json` instead of provider bytes.

Canonical roots group distinct atomic subfindings. Exact compatible duplicates
can collapse; related-finding suggestions only affect presentation. Every
non-gating atomic has stable exclusion reason codes. Counts and ordering are
shared across run completion, report, findings, status, and dashboard.

## Configuration and prerequisites

Migration preserves explicit roster, model order, effort, quorum, topology
acknowledgements, applicability, and gate thresholds. A new five-model profile
defaults to three passes from three provider groups. Existing strict 5-of-5
policies remain strict. Legacy heartbeat values outside the v7 range are brought
within its 1,000–300,000 ms limits during migration.

Change-readiness is explicit: set `kind = "change_readiness"`. The TUI populates
the seven required selectors under `/request/pull_request`: `id`, `url`, `title`,
`description`, `work_items`, `validation`, and `contract_impact`. The caller
supplies those values in request 3. Missing or invalid required values skip the
lens before provider contact and make coverage partial. Review Mesh does not
fetch PR metadata or Git history.

`config apply --json` retains outer schema 1 and checks the expected revision
before validating/migrating the desired config. Confirm derived attested proof
with `confirm_attested_coverage: true`. Read-only commands never save migration.

Shallow-history diagnostics distinguish unavailable base refs, unavailable
merge bases, and other collection failures. They provide safe Git checks
without fetching or changing the reviewed checkout.

## Artifact inspection

The artifact stores a preterminal content digest; the terminal public event and
run index hold the finalized file digest. Readers verify indexed file identity
and bytes. A removed/replaced authoritative details file is an error. Directly
read orphan artifacts report `final_digest_unavailable` when no published final
digest is supplied. Historical change-scoped artifacts without coverage proof
retain their reported values and cannot be reused as verified clear v9 gates.
