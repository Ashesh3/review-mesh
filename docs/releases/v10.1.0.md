# Review Mesh v10.1.0

Review Mesh v10.1.0 improves native SDK review completion, cancellation, progress reporting, and context recovery. It also makes native review results reflect model assessments without claiming independently verified file coverage.

## Native review behavior

- Native agents receive the trusted reviewer instructions, branch and changed-file context, and read-only workspace/Git tools, then choose what to inspect.
- Legacy `change_coverage` settings remain readable but do not impose native file-read obligations. Native results use `status = "not_applicable"` and `proof_kind = "unknown"`; historical `native_scope_attestation` is optional metadata.
- Structured result and candidate-decision validation remain enforced. Native findings and adjudications retain the model's evidence and limitations without independently rechecking source citations. Command-only reviews retain their existing coverage and evidence contracts.
- `strict-evaluation` runs every applicable configured model, including remaining independent adjudicators. Model disagreement is retained in the report with an `adjudication_disagreement` warning; operational failures still leave execution incomplete. A completed evaluation can exit `1` with gate findings.

## Reliability improvements

- Corrects Copilot completion waiters, cancellation, and deadlines, and improves Windows Claude process-tree shutdown and cleanup reporting.
- Enforces `no_progress_timeout_ms` using meaningful native activity, including streamed arguments and thinking progress, and coalesces activity records without losing progress.
- Retains sanitized original context and readable plain-text diffs in private SDK session files so agents can consult them after compaction. Large diffs are supplied through native reads instead of duplicated prompt text.
- Keeps Claude's internal compaction text-only through a session-owned loopback transport gated by trusted native compaction hooks, while preserving ordinary review requests and supported cloud authentication.
- Keeps pending required adjudication visible in live results and preserves accepted gate findings across successive adjudicator revisions.
- Makes Windows-only standalone verification check the requested platform without requiring a Linux build.

## Upgrade

Existing SDK configurations remain readable. Consumers that previously used native coverage attestations as an acceptance gate should account for the `not_applicable`/`unknown` coverage metadata and model-assessment behavior described above. Result schemas, reports, historical artifacts, and command-only configurations remain supported.

See [SDK configuration and migration](https://github.com/Ashesh3/review-mesh/blob/v10.1.0/docs/sdk-migration.md) for credentials, model routing, and runtime requirements.

## Validation

- 1,414 source tests passed; 13 opt-in or platform-specific tests were skipped in the default suite.
- Formatting, application/test TypeScript checks, and the portable build passed.
- All four standalone acceptance checks passed against the Windows and Linux release binaries.
- All nine bundled-runtime checks passed on each platform, including startup, handshake, and shutdown for Codex, Claude, and Copilot without separately installed CLIs.
- All 24 Claude runtime tests passed with a local fixture provider, including native compaction, retained-context reads, read-only Git access, denied writes, and cancellation.
- A new strict-adjudication regression reproduced the stale adjustment bug before the fix; all 58 related tests passed afterward.

These checks validate the release integration and result contracts, not general model review accuracy.
