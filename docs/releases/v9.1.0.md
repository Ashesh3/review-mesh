# Review Mesh v9.1.0

The local dashboard now centers on review progress: compact circular run
stages, one row per logical reviewer, expandable model attempts, and a resizable
bottom inspector. The approved editable design is included as `design.pen`.

## Dashboard

- Redesigned Reviews, live Timeline, Findings, Events, Reviewers, Projects, and
  System views, with searches, filters, selected rows, and detailed inspectors.
- Light, Dark, and System themes selected with sun, moon, and monitor buttons;
  the choice is remembered and System follows operating-system changes.
- Complete live reviewer rosters include queued and deferred model slots, with
  recorded phase, model, adapter, attempt, activity, and timing information.
- Recorded evidence, reviewer results, coverage, and runtime details remain
  available without hiding the timeline. Repeated heartbeat events can collapse.
- Live refresh preserves selection, filters, scroll, and keyboard focus; updates
  arriving during a refresh are queued. Stopped updates are labeled stale.
- Responsive phone layouts, keyboard resizing, accessible theme controls, and
  corrected early-termination stage indicators.

Run `review-mesh serve` to open the dashboard. It remains read-only, loopback-only,
and self-contained in the portable script and standalone executables. No CDN,
frontend runtime installation, or external asset directory is required.

## Compatibility

Public request, configuration, reviewer-result, adjudication, event, and overall
artifact-format versions remain the v9 contracts. The private `resolution`
record writer advances from schema 1 to schema 2 to persist safe roster metadata
before reviewers start. This release reads both versions and validates each
record against its declared manifest version. Use v9.1.0 or newer to inspect
artifacts written by this release; older v9.0.0 readers reject resolution 2.

Historical artifacts without queued-model metadata remain readable and show
unrecorded fields explicitly. Credential values, instructions, provider chat,
adapter commands, and endpoint values are not exposed by the dashboard.
